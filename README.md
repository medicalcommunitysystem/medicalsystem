# 社区医疗系统：A 成员交付与小组接口

本分支实现 M01 患者管理、M03 预约挂号、M08 登录与用户，以及程序入口、角色菜单。数据库、药品和处方代码已合并 `origin/main` 的 `d15b7f1`，保留 C 的原有接口。B 的医生管理、接诊、病历和菜单入口尚未出现在该远程版本中；这里没有冒充实现这些模块。

## 现有数据库升级与启动

1. 不要为了启动程序重新执行 `sql/init_db.sql`：该组员脚本包含删表操作。
2. 在 Navicat 中选择已有的 `medical_system` 库，通过“运行 SQL 文件”执行 `sql/member_a_upgrade.sql`，设置遇错停止，不要忽略错误。这是增量升级，不删除原有患者、医生、预约等业务记录。升级前应备份数据库，并暂停其他客户端写入。
3. 如出现跨角色重名或重复有效预约，升级会报错，必须先由小组确认数据处理方案；脚本不会擅自删除冲突记录。DDL 会隐式提交，脚本不是一次性原子事务；修正冲突后可重新执行。
4. Windows 编译：

   ```powershell
   mingw32-make -f Makefile.member-a all
   ```

5. 启动：

   ```powershell
   .\scripts\run-member-a.ps1
   ```

启动脚本会安全提示输入 MySQL 用户名和密码，不把密码写入文件、源码或命令行参数。可设置 `MEDICAL_DB_HOST`、`MEDICAL_DB_NAME`、`MEDICAL_DB_PORT`；默认主机 `127.0.0.1`、数据库 `medical_system`、端口 `3306`。`MEDICAL_DB_USER`、`MEDICAL_DB_PASSWORD` 由进程环境传入。

注意两种密码不同：启动时输入的是 **MySQL 数据库连接密码**；登录菜单输入的是 **患者、医生或管理员的应用账号密码**。

组员原脚本中的旧密码数据不被当作安全哈希接受，也没有明文登录回退。已有旧账号需要由持有数据库管理员凭据的操作者初始化一次：

```powershell
.\scripts\run-member-a.ps1 -InitializePassword
```

该命令只初始化尚未使用本项目安全哈希格式的账号，拒绝覆盖已经设置好的安全密码。它是本地数据库管理员工具，不是面向普通用户开放的找回密码接口。初始化不改变账号停用状态。

Linux/MySQL 8 开发环境使用 `make -f Makefile.member-a`，需要 MySQL C 开发库、`mysql_config` 和 OpenSSL 开发库。此入口是 A 的附加构建文件，不覆盖 B 负责的最终小组 Makefile。Windows 默认使用本机开发库路径，其他成员应根据安装位置覆盖 `MYSQL_ROOT` 和 `MYSQL_COMPAT_INCLUDE`，不要修改系统环境或复制别人的数据库密码。

## 功能与规则

- 患者自助注册和管理员新增共用创建流程。编号格式为 `P` + 四位年份 + 八位序号，序号由数据库事务串行分配；调用成功后填写 `Patient` 的编号、注册时间和状态。
- 注册检查必填、UTF-8、数据库字符上限、非负年龄，以及用户名和身份证唯一。未擅自增加身份证校验位、手机号制式、密码强度等未统一的业务规则。
- 三类角色真实查询数据库登录。会话只在认证和事务提交都成功后建立，统一提供角色检查与账号有效性检查。
- 连续五次密码错误锁定十分钟；失败次数和截止时间保存在数据库中，关闭程序不会清除。到期恢复尝试，成功登录清零。数据库错误、格式错误和未初始化密码不计为密码错误。
- 所有角色可验证旧密码后修改本人密码。密码使用系统密码库的 PBKDF2-HMAC-SHA256、600000 次迭代、随机盐，不保存明文。Windows 使用 CNG，Linux 使用 OpenSSL。格式长度适配现有 `VARCHAR(100)`。参数参考 [OWASP 密码保存指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。
- `auth_hash_password()` 是原预留密码哈希职责的实现。它增加 `auth_` 前缀，是为了避免与 MySQL 头文件自带的 `hash_password()` 重名。B/C 新代码应使用此命名，不要通过宏修改 MySQL 头文件。
- 患者只能通过会话编号查询本人档案、修改本人联系方式、挂号、查询和取消本人预约。管理员可新增、查询、修改、注销患者。修改档案不顺带修改编号、登录账号、密码或状态。
- 注销是软删除；账号不能再登录或挂号，旧会话也会在执行操作时重新检查有效性。保留历史关联记录。
- 导出采用 UTF-8 CSV 文本，只允许管理员操作，排除密码与身份证号，转义引号并防止表格公式注入；独占创建，绝不覆盖已有文件。写入中途失败可能留下不完整的新文件，错误返回不能当作成功导出。
- 挂号检查患者、医生有效，日期合法且不早于数据库当天，时段非空且不超过十个字符。同患者、同医生、同一天，状态 `0/1` 都视作有效预约，状态 `2` 已取消不占唯一键；取消后可以重挂。
- 仅本人待就诊预约可取消。零条受影响表示没有符合全部条件的记录，不泄露预约究竟属于谁。重复取消返回未找到。
- 医生查看本人当天待就诊列表，管理员查看全部预约；A 的列表入口支持分页。
- 按较严格的权限矩阵，管理员目前只查询预约，不取消预约；小组明确授权后再扩展。接诊、创建就诊记录和更新已就诊状态归 B，A 不另写一套 `appointment_take()`。

## 给 B/C 的接口与数据库说明

- `UserSession` 在 `include/session.h`；本人身份来自会话，不能使用菜单输入的其他人编号绕过权限。用户名缓冲是 UTF-8 字节容量，数据库上限仍为 50 个字符。头文件布局变化后须重新编译所有模块。
- `auth_require_role()` 只检查会话角色；实际业务入口再使用 `auth_require_active()` 拒绝已经停用的会话。二者均为 `AUTH_OK == 0`。
- `auth_username_exists()`：`1` 已使用、`0` 可用、负数错误。不能写成 `if (!auth_username_exists(...))` 后忽略数据库错误。B 创建医生前可调用此接口；最终并发保障来自数据库。
- `t_auth_account` 是三类角色共用的账号唯一注册表和锁定状态表。迁移安装的触发器会在患者、医生、管理员新增、改名、状态更新及删除时同步注册表，并参与原语句事务；即使 B 直接新增医生，跨角色重名也会被数据库拒绝。失败不得吞掉数据库的重复键错误。
- 原管理员表没有停用字段，其停用状态保存在注册表。患者和医生状态随各自业务表同步，管理员状态不被修改密码自动重置。
- `t_appointment.effective_booking` 生成列及组合唯一键防止并发重复挂号。`t_member_a_sequence` 分配患者编号。`t_member_a_schema` 的完成标记只在整个脚本成功后写入，程序拒绝在升级未完成时启动。升级在维护窗口执行，确保三张账号表在回填与安装触发器期间不被并发修改。
- 在 C 的 `db.h/db.c` 上增补了 `db_query_params()`、`db_execute_params()`、`db_connect_port()`，保留旧函数签名和含义。参数数组只支持文本或 SQL NULL；整数业务字段可绑定文本，由 SQL 转换；`LIMIT/OFFSET` 只格式化已经验证的 C 整数。
- 参数查询使用真实 MySQL prepared statement，可继续使用原来的 `db_fetch_row()`、`db_get_field()`、`db_get_field_by_name()`。字段指针只在当前结果有效，下一次查询、执行、事务操作或释放结果前必须复制。单字段结果缓冲上限 1 MiB，超限明确失败。实现参考 [MySQL 8 C API](https://dev.mysql.com/doc/c-api/8.0/en/mysql-stmt-store-result.html)。
- 查询成功返回 `ERR_OK`，取行返回 `1/0/负数`，写操作返回 `受影响行数/负数`。资料未变化时，UPDATE 返回零并不一定代表记录不存在；取消预约则严格要求影响一条。
- A 顶层写业务拥有自己的事务；辅助函数不擅自提交。C 原有禁止嵌套事务的行为保留。B 接诊和 C 开方仍须在各自同一连接、同一事务内完成。
- A 的挂号菜单暂用只读医生列表适配器，因为远程仓库尚无 B 的医生查询公共接口。B 发布后替换适配器即可，不影响挂号权限和数据库校验。
- 主菜单接入 C 已有药品列表和按身份限定的处方查询。C 的写业务菜单仍由 C 提供；没有把低层、不带会话参数的函数直接当作安全用户入口。

## 适用边界

这是本地终端课程项目，不是可直接对公网部署的医疗后端。数据库公共库仍是每进程单连接、非线程安全；没有 HTTP/JWT、会话过期、网络层限流、多因素认证、审计体系或完整医疗隐私合规。普通账号也不应持有高权限数据库凭据，生产部署需要单独的服务边界。控制台密码输入拒绝无回显能力的管道；强制终止进程时的终端恢复需要生产级信号处理。

本机已验证 Windows 编译和独立临时数据库联调；测试代码留在本地。Linux 分支仍须在课程指定 Linux 环境重新编译验收，不能用 Windows 结果替代。
